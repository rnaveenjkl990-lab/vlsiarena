## Full Task Specification

Four-client round-robin arbiter with dynamic masked priority rotation, atomic transfer lock, and acknowledge-driven pointer updates.

Your task: implement the rr_arbiter_locked design described in this specification.
Write the complete synthesizable SystemVerilog module with the interface below.
  - clk: input, width 1
  - rst_n: input, width 1
  - req: input, width 4
  - lock: input, width 1
  - grant_ack: input, width 1
  - grant: output, width 4
  - grant_valid: output, width 1
  - grant_id: output, width 2
Behavior to implement: Reset synchronously clears grant to 4'b0000, grant_valid to 0, grant_id to 2'b00, and pointer to client 0 priority.; Arbitration priority is cyclic: client (P+1)%4 has highest priority, down to client P having lowest priority.; When lock=1 and active grant exists with corresponding req asserted, the current grant must remain held unchanged.; Pointer updates to granted client index only on clock edges where grant_valid=1 and grant_ack=1, provided lock=0..
Corner cases your design must handle: All 4 clients requesting simultaneously results in round-robin succession client 0 -> 1 -> 2 -> 3 -> 0 across successive acks.; Assertion of lock without an active grant produces standard arbitration without locking.; Assertion of grant_ack without grant_valid leaves the priority pointer unchanged.; Single active client keeping req high receives continuous grant while rotating pointer stays on that client..
Task kind: rtl_design.
